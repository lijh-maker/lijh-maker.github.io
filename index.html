让中职生真正理解 if 选择结构：三个教学关键点

这是一篇示例文章，用来展示博客的文章排版效果（标题、引用、代码块、表格、列表）。
内容可以随意修改或删除，换成你自己的教学反思。

教《Java 编程基础》的 if 选择结构时，最难的不是语法本身，而是让基础薄弱的学生建立起”程序会在这里分岔”的直觉。下面是三个在课堂上验证过比较有效的做法。

一、先用生活情境，再出现语法

不要一上来就写 if (条件) { }。先给一个学生能秒懂的场景：

自由虾旅行平台要判断门票价格——成人票 100 元，学生票半价。

学生脑子里已经有”如果是学生就打折”这个判断，此时再把它翻译成代码，阻力小很多。

关键点：先让学生预测输出，再运行验证。预测错了的地方，恰恰是概念缺口所在。

二、把”执行顺序”讲成排队过关

多重 if 和嵌套 if 的区别，学生常常混淆。用一个比喻能省掉大量解释：

结构 生活比喻 执行特点
多个并列 if 一排独立的关卡，每个都要过一遍 每个条件都会判断，互不影响
if-else if 一条通道，进了一扇门就不再看后面的门 命中一个就跳出，后面的不再判断
嵌套 if 关卡里面还有关卡 外层不通过，内层根本没机会执行

课堂上可以故意”制造错误现场”：把 else if 改成并列 if，让学生看输出多了几行，再问为什么。自己发现的错误，比老师讲十遍都记得牢。

三、语法脚手架常驻黑板

基础薄弱的班级，最怕写到一半忘了括号和分号。在黑板固定区域留一块”脚手架”，整节课不擦：

学生写代码时抬头就能对照，减少因为语法细节受挫而放弃的情况。等全班都熟了，再逐步擦掉。

常见错误速查

错误写法 后果 纠正
if (score = 60) 变成赋值，条件恒为真 用 == 做比较
if (score > 60); 多了一个分号，if 管不到下面的语句 去掉分号
忘记大括号 只有紧跟的一行受 if 控制 即使一行也写上 { }
